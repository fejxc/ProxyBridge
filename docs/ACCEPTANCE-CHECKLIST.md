# ProxyBridge 真实环境验收清单（发布门槛）

本清单是每次发布前的**人工验收门槛**：在固定的 Mac + Linux 环境上执行全部场景，结果填入末尾记录表。
未完成验收的版本不得打 tag 发布（`docs/RELEASE.md` 流程第 2 步）。
所有自动化能覆盖的部分（类型检查、196 项冒烟、CI XCTest）不在此重复；本清单只覆盖**必须真实链路才能证明**的行为。

## 固定环境要求

- Mac：安装本版本 DMG（从 Release 下载，非本地构建）；Clash 类客户端（含 TUN 模式开关）
- Linux：SSH 可达；已安装 `curl`；HTTP 入口场景需 `privoxy`；容器环境优先（覆盖无 ss/netstat 的最小镜像）
- 记录工具：`~/Library/Logs/ProxyBridge/app.log`（App 自动落盘）+ Linux 侧终端输出

## 场景矩阵

### A. 连接模式（三选一全过 = 该组通过）

| # | 场景 | 操作 | 预期 |
|---|---|---|---|
| A1 | 静态转发 | Mac 启动 Clash（回环 HTTP/SOCKS 入口）→ App 选静态模式连接 | 状态到「已连接（绿色）」；Linux `curl --proxy http://127.0.0.1:7890 -I https://<业务目标>` 返回 2xx/401 |
| A2 | 动态 SOCKS5 | Clash 切 TUN（无本地端口）→ App 选动态模式连接 | 已连接；Linux `curl --socks5-hostname 127.0.0.1:17890 -I https://<目标>` 通过 |
| A3 | 自动模式 | 静态入口可用时连接 → 断开 Clash → 重连 | 第一次走静态；入口消失后自动回退动态 SOCKS5（面板如实显示模式变化） |

### B. 自愈恢复（App 在前台，观察面板与日志）

| # | 场景 | 操作 | 预期 |
|---|---|---|---|
| B1 | Clash 端口漂移 | 连接中修改 Clash 混合端口并重启 Clash | 面板出现「端点变化 → 实测 → 无缝切换」，SSH 不重启即恢复已连接 |
| B2 | Clash 进程退出/重启 | 连接中完全退出 Clash 数十秒再启动 | 本地检查降级 → 代理恢复后自动回升/切换，无需人工 |
| B3 | 节点切换 | 连接中在 Clash 切换不同地区节点 | 面板「出口」徽标变化 + 立即自动重验；结果如实（绿或橙） |
| B4 | 网络切换 | Mac Wi-Fi 断开重连（或切热点） | 秒级重建隧道（不等 90s）；若配密码未记住也不再重复询问（1.4.5+） |
| B5 | 远端端口冲突 | 在 Linux 手工挂起一条同端口僵尸 sshd（`nohup ssh -N -R ... &` 后 kill 客户端），App 重连 | 3 分钟窗口自动重试；1.4.3+ 弹诊断卡可一键清理自家残留并自动重连 |
| B6 | 休眠唤醒 | 合盖 ≥1 分钟再唤醒 | 隧道按「自动重连」设置恢复或如实保持终态 |
| B7 | Mac 重启 / App 崩溃 | 重启 Mac（或 `kill -9` App）再启动 | 启动日志出现孤儿 ssh 清扫记录（若有残留）；连接恢复正常 |

### C. Linux 侧功能

| # | 场景 | 操作 | 预期 |
|---|---|---|---|
| C1 | Codex HTTP 入口 | Linux `export https_proxy=http://127.0.0.1:7890` 后跑 Codex/真实业务请求 | 业务可用；面板 HTTP CONNECT 显示已验证 |
| C2 | 缺 Privoxy | 临时移除 privoxy 后连接 | 如实显示「未安装 Privoxy」+ 安装指引卡；SOCKS5 不受影响 |
| C3 | 业务验证目标 | 服务器配置填写实际业务 URL 后「检查连接」 | 面板远端行显示该目标域名；结论与该目标实际可达性一致 |

### D. 更新链路（1.4.5+）

| # | 场景 | 操作 | 预期 |
|---|---|---|---|
| D1 | 应用内更新 | 安装旧版 → 发布新版后点横幅「自动更新」 | 下载进度 → 校验 → 自动重启进入新版；/Applications 中版本正确 |
| D2 | 校验失败防护 | （开发者自测）人为破坏下载/校验环节 | 绝不安装，如实报错并保留发布页路径 |
